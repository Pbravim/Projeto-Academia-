# DTOs com Zod (substitui class-validator/class-transformer) — Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Trocar class-validator/class-transformer por Zod, movendo a fonte de verdade do wire para schemas em `packages/contracts` — as interfaces TS passam a ser `z.infer` dos schemas (fonte única para API e mobile).

**Architecture:** Um `ZodValidationPipe` global mantém o contrato do pipe atual (`transform(value, { metatype })`), lendo um `static zodSchema` na classe DTO — assim os specs existentes (que passam `metatype`) e o teste de `design:paramtypes` do controller continuam válidos. Os schemas dos 9 row types do sync vivem no `packages/contracts` ao lado das interfaces (que viram `z.infer`); os DTOs da API viram cascas finas. `.strict()` replica o `forbidNonWhitelisted` atual (chave desconhecida = 400).

**Tech Stack:** zod ^3 (ou ^4 se o npm resolver — API idêntica para o que usamos), NestJS 10, jest.

## Global Constraints

- **Custo/benefício (leia antes de executar):** o único ganho real é a fonte única de tipos+validação no contracts. Se isso não for desejado, NÃO execute este plano — a validação atual já cobre tudo.
- Paridade com o pipe atual (`whitelist + forbidNonWhitelisted + transform`): chave desconhecida → `BadRequestException` (400); tipos errados → 400; datas ISO-8601 validadas.
- Compat com clientes antigos preservada: `exerciseAlternatives` continua opcional no request.
- O mobile NÃO pode passar a carregar zod em runtime: importa apenas `import type` do contracts (z.infer some na compilação).
- Specs que precisam continuar verdes sem reescrita de intenção: `sync-request.dto.spec.ts` (10 casos), `validation.spec.ts`, `sync.controller.spec.ts` (metatype no `design:paramtypes`).

```ts
// apps/api/src/validation.ts (arquivo completo)
import { BadRequestException, Injectable, type ArgumentMetadata, type PipeTransform } from '@nestjs/common';
import type { ZodType } from 'zod';

type WithZodSchema = { zodSchema?: ZodType };

/**
 * Pipe global de validação via Zod. A classe DTO declara `static zodSchema`;
 * `.strict()` nos schemas replica o antigo forbidNonWhitelisted (chave
 * desconhecida = 400 explícito, nunca descarte silencioso).
 */
@Injectable()
export class ZodValidationPipe implements PipeTransform {
  transform(value: unknown, metadata: ArgumentMetadata) {
    const schema = (metadata.metatype as WithZodSchema | undefined)?.zodSchema;
    if (!schema) return value;
    const result = schema.safeParse(value);
    if (!result.success) {
      throw new BadRequestException(
        result.error.issues.map((i) => `${i.path.join('.') || '(root)'}: ${i.message}`),
      );
    }
    return result.data;
  }
}

export function buildValidationPipe(): ZodValidationPipe {
  return new ZodValidationPipe();
}
```

(`main.ts` não muda: já chama `app.useGlobalPipes(buildValidationPipe())`.)

const iso = z.string().datetime({ offset: true }); // equivale ao @IsISO8601
const isoNullable = iso.nullable();
const id = z.string().max(255);
const TEXT_MAX = 10_000;

export const treinoSyncRowSchema = z.object({
  id,
  updatedAt: iso,
  deletedAt: isoNullable,
  name: z.string().max(255),
  objetivo: z.string().max(TEXT_MAX).nullable(),
  createdAt: iso,
}).strict();

// ... exerciseSyncRowSchema, treinoExercicioSyncRowSchema, sessaoTreinoSyncRowSchema,
// sessaoExercicioSyncRowSchema (inclui movementPatternSnapshot: z.string().max(255).nullable()),
// serieRegistradaSyncRowSchema, registroPesoSyncRowSchema, userSettingSyncRowSchema,

// Numéricos: z.number().int() onde o DTO usa @IsInt, z.number() onde @IsNumber; nullable() onde `| null`.

export const syncChangesSchema = z.object({
  exercises: z.array(exerciseSyncRowSchema),
  treinos: z.array(treinoSyncRowSchema),
  treinoExercicios: z.array(treinoExercicioSyncRowSchema),
  sessaoTreinos: z.array(sessaoTreinoSyncRowSchema),
